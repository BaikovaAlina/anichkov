# Как запустить «Аничков» — без платного сервера

## Что уже готово

- Полностью работающий тренажёр: `index.html`.
- Дизайн по мотивам `BaikovaAlina/trenazhor`: клетчатая бумага, красные поля, меловая доска, стикеры.
- 7 формул, карточки памяти, 7 пошаговых объяснений, 4 вида заданий, проверка себя.
- Проверка равносильных алгебраических ответов; подсказки, разборы и попытки считаются отдельно.
- История последних 20 работ, продолжение незавершённой работы, отчёт TXT.
- Готовый **обработчик отправки в Telegram**, но для реальной доставки его нужно разместить в вашем бесплатном аккаунте Cloudflare и указать секреты.

**В проект не включены действующие токены.** Перевыпустите ранее раскрытые GitHub- и Telegram-токены. Не вставляйте их в `index.html` и не присылайте в чат.

## 1. Посмотреть сайт прямо сейчас

Откройте `index.html` в обычном браузере. Все шрифты, стили, формулы и скрипты встроены: дополнительных файлов и установки библиотек не нужно.

В файловом предпросмотре некоторые браузеры запрещают localStorage и скачивания. На обычном сайте GitHub Pages сохранение работает, если браузер сам его не блокирует.

## 2. Опубликовать в вашем anichkov

Адрес репозитория: https://github.com/BaikovaAlina/anichkov

Если файлы ещё не загружены:
1. Откройте репозиторий под своим аккаунтом GitHub.
2. Выберите **Add file → Upload files**. В пустом репозитории ссылка может называться **uploading an existing file**.
3. Для самого простого запуска достаточно загрузить **`index.html` в корень**. Можно загрузить и остальные файлы проекта, кроме `node_modules`, `test-results` и `site`.
4. Нажмите **Commit changes**, ветка — `main`.
5. Откройте **Settings → Pages**.
6. В **Build and deployment / Source** выберите **Deploy from a branch**.
7. Ветка **main**, папка **/ (root)** → **Save**.
8. Дождитесь успешной публикации. Ожидаемый адрес:

   **https://baikovaalina.github.io/anichkov/**

Это адрес публикации, а не обещание, что Pages уже включён. Состояние видно в Settings → Pages и Actions. Для публичного репозитория достаточно бесплатного GitHub Pages.

> По умолчанию дополнительный workflow не нужен: готовая страница уже собрана. Если предпочитаете сборку через GitHub Actions, шаблон лежит в `deployment/pages.yml`. Перенесите его в `.github/workflows/pages.yml` и выберите Source → GitHub Actions. Используйте один способ публикации, не оба сразу.

## 3. Подключить кнопку «Отправить учителю»

Почему не просто вставить токен в JavaScript? Потому что код статического сайта виден каждому ученику. Получив токен, посторонний сможет управлять вашим ботом. Само нажатие кнопки не защищает секрет.

Схема бесплатная:

**GitHub Pages → только по кнопке → Cloudflare Worker Free → ваш Telegram-бот.**

Нужен бесплатный аккаунт Cloudflare. Оплачиваемый сервер, база данных, домен и платный тариф не требуются для этой схемы в пределах бесплатных лимитов. Не включайте Workers Paid.

### А. Подготовить бота и ваш chat_id

1. В BotFather перевыпустите токен ранее раскрытого бота.
2. Откройте своего бота в Telegram и нажмите **Start**, отправьте `/start`.
3. Нужен числовой ID **именно вашего чата с ботом**, не имя бота и не ID ученика.
4. Чтобы получить ID без публикации токена, запустите на своём компьютере с Python 3:
   ```sh
   python3 scripts/get-chat-id.py
   ```
   На Windows команда обычно `python scripts/get-chat-id.py`.
   Скрипт попросит новый токен скрытым вводом, ничего не сохранит и выведет найденные ID. Выберите свой личный чат. Если у бота уже установлен webhook, скрипт не отключает его — проверьте действующую интеграцию прежде, чем что-то менять.

### Б. Разместить Worker — через браузер, без команд

1. Cloudflare Dashboard → **Workers & Pages → Create application / Create Worker**. Выберите бесплатный Worker.
2. Создайте Worker, например `anichkov-reports`. Откройте **Edit code**.
3. Полностью замените пример кода содержимым **`worker/telegram-worker.mjs`**. Это уже собранный самостоятельный ES-модуль; ничего импортировать дополнительно не нужно. Нажмите **Deploy**.
4. В **Settings → Variables and Secrets** добавьте:

   | Имя | Тип | Значение |
   |---|---|---|
   | `TELEGRAM_BOT_TOKEN` | **Secret** | Новый токен из BotFather |
   | `TELEGRAM_CHAT_ID` | **Secret** | Числовой ID вашего чата |
   | `ALLOWED_ORIGINS` | Text | `https://baikovaalina.github.io` |

   В `ALLOWED_ORIGINS` **не добавляйте `/anichkov/` и завершающий слэш**: это origin, не полный адрес страницы.
5. Примените изменения и ещё раз Deploy. Запишите настоящий адрес вида `https://ИМЯ.ВАШ-ПОДДОМЕН.workers.dev`.

В варианте установки через Dashboard действует приблизительное ограничение отправок в памяти Worker. Для рекомендованного Cloudflare Rate Limiting binding используйте вариант Wrangler из README. Это не авторизация учеников; см. SECURITY.md.

### В. Связать сайт с Worker

1. Откройте `index.html` в редакторе или GitHub → Edit.
2. Найдите `window.ANICHKOV_CONFIG`. Рядом есть единственная настройка:
   ```js
   "reportEndpoint": ""
   ```
3. Вместо пустой строки укажите **настоящий публичный URL вашего Worker с `/report` в конце**. Например, если в Cloudflare у вас адрес `https://ИМЯ.ВАШ-ПОДДОМЕН.workers.dev`, то настройка будет `https://ИМЯ.ВАШ-ПОДДОМЕН.workers.dev/report`.
4. **Не вставляйте туда токен и chat_id.** Сохраните файл и загрузите обновлённый `index.html` в репозиторий.
5. Если работаете с исходниками, внесите тот же адрес в `site-config.json`, выполните `npm run build` и загрузите получившийся `index.html`. При дальнейших сборках значение берётся из `site-config.json`.

### Г. Проверить доставку

1. Откройте **опубликованный GitHub Pages сайт**, не локальный `file://`: только разрешённый origin может отправлять отчёты.
2. Пройдите короткую тренировку, можно специально сделать ошибку и взять подсказку.
3. Нажмите **«Отправить учителю»**, укажите имя, подтвердите состав данных и нажмите **«Отправить в Telegram»**.
4. В вашем чате с ботом должны появиться краткий итог и файл со всеми заданиями, ответами и попытками.
5. Только после подтверждения Telegram сайт показывает **«Отправлено»**. При ошибке остаётся возможность скачать TXT.

**Без настройки Worker тренажёр работает, но реальная отправка не подключена.** Сайт честно сообщает об этом. Никаких сообщений в ваш бот в процессе автоматических тестов не отправлялось.

## Если что-то не работает

| Симптом | Что проверить |
|---|---|
| GitHub Pages показывает 404 | Файл называется `index.html`, находится в корне `main`, включён Pages, публикация завершилась |
| «Telegram пока не подключён» | `reportEndpoint` не заполнен или обновлённый HTML ещё не опубликован |
| Запрос запрещён / 403 | Origin в Worker — ровно `https://baikovaalina.github.io`; открыта опубликованная страница |
| «Учитель ещё не закончил настройку» / 503 | В Worker отсутствуют секреты или не применён Deploy |
| Ошибка доставки / 502 | Токен действующий, chat_id принадлежит вам, вы нажали /start у бота; у группы есть нужные права |
| Слишком много отправок / 429 | Подождать минуту; в классе с общим Wi-Fi ограничение делится между учениками |
| Прогресс пропал | Другой браузер/устройство, приватный режим или очистка данных; синхронизации между устройствами нет |
| Нет подтверждения после ожидания | Отчёт мог успеть дойти. Проверьте чат прежде, чем отправлять повторно |

Подробности разработки и проверок — в `README.md`. Безопасность — в `SECURITY.md`.
